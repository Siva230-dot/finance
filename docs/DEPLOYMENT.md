# Free Deployment Guide

Target (no purchases, provider sub-domains only):

| Part | Provider (free plan) | Address |
|---|---|---|
| Frontend (static Vite build) | Vercel Hobby | `https://<project>.vercel.app` |
| Backend (FastAPI) | Render Free Web Service | `https://<service>.onrender.com` |
| Database | Supabase Free PostgreSQL | managed |

Do **not** use Render's free PostgreSQL for user data (it expires). Do not add a custom domain, paid add-ons or plan upgrades.

## 0. Push the code to GitHub
Vercel and Render deploy from a Git repository. Create a private GitHub repo and push this project (`.env` files are git-ignored — check with `git status` before committing).

## 1. Supabase (database)
1. Create a free project at https://supabase.com → choose a strong database password and a region near your Render region.
2. Project → **Connect** → choose **Session pooler** (IPv4-compatible; Render free instances cannot reach Supabase's IPv6-only direct host).
3. Copy the URI and build `DATABASE_URL`:
   ```
   postgresql+psycopg://postgres.<project-ref>:<URL-ENCODED-PASSWORD>@aws-0-<region>.pooler.supabase.com:5432/postgres?sslmode=require
   ```
   URL-encode special characters in the password (`@` → `%40`, `#` → `%23`, …).
4. Nothing else is needed; tables are created by Alembic on the first Render start.

## 2. Render (backend)
1. https://dashboard.render.com → **New → Blueprint** → select the repo. `render.yaml` defines `ai-financemate-api` (plan: free, root `backend`).
   *Alternatively* New → Web Service with: Root Directory `backend`, Build `pip install -r requirements.txt`, Start (from `render.yaml`), Health check `/api/v1/health`, Instance type **Free**.
2. Set the variables marked `sync: false`:
   | Key | Value |
   |---|---|
   | `DATABASE_URL` | Supabase session-pooler URL from step 1 |
   | `GROQ_API_KEY` | your Groq key |
   | `FRONTEND_URL` | `https://<project>.vercel.app` (use a placeholder now, update after step 3) |
   | `CORS_ORIGINS` | same as `FRONTEND_URL` |
   `JWT_SECRET_KEY` is generated by Render; `APP_ENV=production`, `GROQ_MODEL=openai/gpt-oss-120b` come from the blueprint.
3. Deploy. The start command runs `alembic upgrade head` then gunicorn. Verify:
   ```bash
   curl https://<service>.onrender.com/api/v1/health
   # {"status":"ok","database":"ok","llm_configured":true,"environment":"production"}
   ```
4. Optional demo data (synthetic only): Render Shell → `python -m app.scripts.seed_demo`. Set `DEMO_PASSWORD` env first if the demo will be public.

## 3. Vercel (frontend)
1. https://vercel.com/new → import the repo.
2. **Root Directory:** `frontend`. Framework preset: Vite (build `npm run build`, output `dist`; `vercel.json` adds SPA rewrites and security headers).
3. Environment variable: `VITE_API_BASE_URL = https://<service>.onrender.com/api/v1` (Production and Preview).
4. Deploy and note the URL `https://<project>.vercel.app`.

## 4. Connect them
Back in Render set `FRONTEND_URL` and `CORS_ORIGINS` to the exact Vercel URL (no trailing slash) → Save (redeploys). For preview deployments add their URLs comma-separated if needed.

## 5. Verify the live deployment
- Open `https://<project>.vercel.app` → landing page loads.
- Register a new account → dashboard.
- Add a transaction; import a small CSV; open JOCASTA and ask "Show my last five expenses".
- `https://<service>.onrender.com/api/docs` should return 404 (docs disabled in production).

## Production environment checklist
- [ ] `APP_ENV=production`
- [ ] `DATABASE_URL` uses the Supabase **session pooler** with `sslmode=require`
- [ ] `JWT_SECRET_KEY` ≥ 32 random chars (Render-generated)
- [ ] `GROQ_API_KEY` set only in Render
- [ ] `GROQ_MODEL` is a currently supported Groq model (check https://console.groq.com/docs/models)
- [ ] `FRONTEND_URL` and `CORS_ORIGINS` = exact Vercel URL
- [ ] `VITE_API_BASE_URL` in Vercel = Render URL + `/api/v1`
- [ ] No `.env` files committed
- [ ] Health endpoint returns `database: ok`

## Free-tier behaviour & quotas
- **Render Free** sleeps after ~15 minutes idle; the first request can take ~1 minute. The frontend uses a 60 s timeout, retries 5xx/network errors and shows "server may be waking up" messages. Free instance hours are limited per month — check the Render dashboard.
- **Supabase Free** pauses projects after a period of inactivity and has database-size/egress limits — check the project's Usage page. Paused DB → API returns `503 database_unavailable`; restore the project from the dashboard.
- **Groq** free/developer tiers have rate limits; JOCASTA shows a rate-limit message and the SDK retries with backoff.
- **Vercel Hobby** has bandwidth/build limits; the static build is small (~250 kB gzip JS).
- Uploaded files are never written to Render's ephemeral disk beyond a temp file deleted during the request.

## Troubleshooting
| Symptom | Fix |
|---|---|
| Browser shows CORS error | `CORS_ORIGINS` must exactly match the Vercel origin (scheme + host, no trailing slash); redeploy Render |
| Health shows `database: unavailable` | Wrong pooler URL/password encoding, Supabase project paused, or missing `sslmode=require` |
| `RuntimeError: JWT_SECRET_KEY must be set` | Set/generate `JWT_SECRET_KEY` in Render |
| Render build fails on Python version | Ensure `PYTHON_VERSION=3.12.10` env (in blueprint) |
| 404 on page refresh in Vercel | Root Directory must be `frontend` so `vercel.json` rewrites apply |
| JOCASTA says model not configured | Set `GROQ_API_KEY` in Render and redeploy |
| JOCASTA errors after a Groq model deprecation | Update `GROQ_MODEL` to a currently listed production model |
| Out-of-memory on Render | Keep `--workers 1` (free instance has 512 MB) |
